AEGIS TECHNOLOGIES — PASSWORD & AUTHENTICATION POLICY
Effective: June 1, 2024 | Version: 3.1
Classification: Internal — All Personnel
Owner: CISO | Review: Semi-Annual | Compliance: SOC 2, ISO 27001, FedRAMP

1. PURPOSE
Establish minimum requirements for password creation, management, authentication
methods, and credential handling across all Aegis Technologies systems and services.

2. SCOPE
Applies to: All employees, contractors, third-party vendors, service accounts,
and automated systems accessing Aegis information assets.

3. PASSWORD REQUIREMENTS
Minimum Length: 16 characters (passphrases encouraged)
Complexity: No composition rules (NIST SP 800-63B compliant)
- No mandatory rotation (expiration disabled)
- Change required only on compromise evidence or annually for service accounts
Prohibited: Common passwords (checked against HaveIBeenPwned + internal blocklist),
context-specific words (company name, product names, username, email)
History: Last 24 passwords cannot be reused
Lockout: 5 failed attempts → 15 min lockout → admin unlock or self-service reset

4. MULTI-FACTOR AUTHENTICATION (MFA) — MANDATORY
All human access to:
- Corporate identity provider (Okta): FIDO2/WebAuthn (YubiKey) or TOTP
- VPN/Zero Trust Network Access: FIDO2 required
- Production systems (AWS, GCP, Kubernetes, GitHub): FIDO2 required
- Source code repositories: FIDO2 required
- Privileged access workstations (PAW): FIDO2 + certificate-based auth
- Email (Google Workspace): FIDO2 or TOTP

Exceptions: Break-glass accounts (documented, time-limited, CISO approval)
SMS/Voice OTP: Prohibited for all personnel (SIM swap risk)

5. PASSWORD MANAGERS
Approved: 1Password Business (company-provided), Bitwarden Enterprise
Requirements:
- Master password: ≥ 20 chars, unique, not used elsewhere
- MFA on vault: FIDO2 required
- No password reuse across personal/work vaults
- Emergency kit: Printed, sealed, stored in physical safe (not digital)

6. SERVICE ACCOUNTS & SECRETS
- No hardcoded secrets in code, config files, CI/CD variables, or containers
- All secrets in HashiCorp Vault (dynamic secrets preferred)
- Service account passwords: 32+ char generated, rotated every 90 days (auto)
- Kubernetes: ServiceAccount tokens (bound, audience-restricted, TTL 1hr)
- Cloud: Workload Identity / IAM Roles for Service Accounts (no keys)
- CI/CD: OIDC token exchange (GitHub Actions → AWS/GCP/Vault), no long-lived keys

7. PRIVILEGED ACCESS MANAGEMENT (PAM)
- Tier 0 (Domain/Identity): Dedicated PAW, FIDO2 + cert, session recorded
- Tier 1 (Servers/Applications): Just-in-Time (JIT) access via Teleport, max 4 hr
- Tier 2 (Workstations/Endpoints): Standard user, admin via JIT (max 1 hr)
- All privileged sessions: Recorded, keystroke-logged, retained 1 year
- Break-glass: Pre-provisioned accounts, dual approval, auto-expire 4 hr

8. CREDENTIAL SHARING — PROHIBITED
- No sharing of personal credentials (verbal, written, chat, email, ticket)
- Team access via: Shared vaults (1Password), group-based RBAC, service accounts
- On-call credentials: Rotated per shift, stored in Vault, accessed via approved tool
- Violation: Immediate account lock, security review, potential termination

9. PHISHING RESISTANCE
- Annual simulated phishing: All personnel, results anonymous/aggregated
- Click rate > 5%: Mandatory focused training (not punitive)
- Report phish: Forward to phish@aegistech.com or use "Report Phishing" button
- High-fidelity simulations: Pre-approved by CISO, legal notified

10. OFFBOARDING & ACCESS REVOCATION
- Voluntary: Access revoked at separation time (HR triggers via Workday → Okta)
- Involuntary: Access revoked BEFORE notification (coordinated HR/IT/Security)
- Service accounts: Audited quarterly, orphaned accounts disabled
- Personal devices: MDM wipe corporate profile, verify credential removal

11. INCIDENT RESPONSE INTEGRATION
- Credential theft suspected: Immediate reset + MFA re-enrollment + session revocation
- Compromised service account: Rotate secret, audit access logs, assess blast radius
- MFA fatigue attack: Number matching / location context enforced on all push MFA

12. COMPLIANCE & AUDIT
- Quarterly: Automated scan for password reuse, MFA gaps, stale service accounts
- Annual: Penetration test includes authentication bypass attempts
- Evidence: Okta logs → SIEM (1 yr hot, 7 yr cold), Vault audit logs (7 yr)
- FedRAMP: MFA required for all non-public endpoints, FIPS 140-2 validated modules

13. EXCEPTIONS & WAIVERS
- Business justification required, documented in ServiceNow
- CISO approval (Director+ for Tier 2, VP+ for Tier 0/1)
- Maximum duration: 90 days, auto-expire, renewal requires re-justification
- Compensating controls mandatory (e.g., IP allowlist, enhanced monitoring)
